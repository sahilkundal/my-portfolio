Case study 04 · Design Automation

Designing my own workflow

An AI-assisted annotation engine that closes the gap between a coded interface and its original UX spec.

My Role
Design automation, solo build
Timeline
2025 —
Tools
Cline, React/HTML/CSS
Org
Samsung R&D Institute India
01

The problem

Design-to-development handoff kept losing fidelity in the gap between a coded interface and its original UX spec. Every release cycle, someone had to manually re-read a spec, open the built interface, and write down what changed, what was missed, and what still needed a decision — a task that was repetitive, easy to get wrong under deadline pressure, and never actually removed from anyone's plate no matter how many times it was done.

01

Spec drift

A coded screen quietly diverges from its original spec over several sprints, and nobody notices until QA or a stakeholder flags it.

02

Manual annotation

Writing structured, readable annotations by hand for every screen change was slow and inconsistent between reviewers.

03

Disconnected tracking

Fixes surfaced in review had to be manually re-typed into Jira as separate tickets, losing context in the process.

02

What I built

An AI-assisted UX Annotation Engine that analyzes coded interfaces against UX specifications and auto-generates structured annotation documentation — plus automation tooling that generates workflow and architecture diagrams directly from code, and Jira automation for card creation, assignment, and status recommendations.

INPUTCoded interface + UX spec
→
ANALYZEAI diff against spec intent
→
ANNOTATEStructured documentation
→
ACTJira cards, auto-assigned
03

Why this matters

Most designers treat AI as a tool for making screens faster. I treat it as a tool for making the process around screens faster — the same systems instinct from the design-system work, applied to my own workflow instead of a component library.

01

Documentation stops decaying

Annotations are generated from the current state of the build, not from memory of what the spec used to say.

02

Review time goes to judgment, not transcription

The tool surfaces the diff; the reviewer spends their time deciding what matters, not typing it up.

03

Handoff becomes a byproduct, not a task

Diagrams and tickets are generated as a side effect of the analysis step instead of a separate chore afterward.

04

Reflection

This is a small project by scope, but it changed how I think about my own tools: the same discipline I'd apply to a component library — inventory the repeated problem, find the reusable rule, automate the boring part — works just as well pointed at my own workflow as it does pointed at a design system.
